# Xiequ 白名单安全与恢复约定

- 管理接口只允许 HTTPS，必须验证证书；不会跟随重定向或降级到 HTTP。
- 默认地址为 `https://op.xiequ.cn/IpWhiteList.aspx`。历史 HTTP 配置不会被自动改写，刷新将在发送请求前失败；请显式核对并保存 HTTPS 地址。
- 本次仅以不带 UID/UKEY 的请求确认 HTTPS 端点可达，未验证真实账号或白名单修改能力。
- 设置接口的 `state.managed_ips` 始终返回数组，包括全新配置和空状态；其他字段继续按原契约校验。存储状态损坏仍返回错误。
- 网络请求前保存本次尝试时间；请求取消后使用独立的 3 秒有界上下文保存结果。自动刷新继续遵守原有冷却间隔，手动刷新仍可显式跳过冷却。
- Add 之前持久化当前身份及配置代次的 pending-add，并在备注尾部附加随机操作标记。备注总长保持在 80 字节内，必要时按完整字符截短用户备注。
- Add 发送前，在同一事务内检查配置代次和状态 CAS，并占用持久账号操作屏障。占用成功后即视为可能已发送；进程崩溃、取消、锁连接断开、超时、空列表和 marker 阳性都不能自动解除。历史未知 Add/Del 屏障均继续保留。
- 远端提交后响应或验证丢失时保留原操作 token、IP、备注 marker 和配置 scope。新建 Manager 仅可读取列表并恢复同配置代次的归属，返回 `operation_unknown` 且 `ok=false`，禁止再次 Add/Del；换 UKEY、重启和 A→B→A 不能绕过。
- 只有原发起调用取得完整、明确成功的响应，再用列表核验其精确操作结果，并以同一个 operation token 原子保存完成状态后，才允许后续变更。任一保存结果歧义或 CAS 失败继续保留屏障。本版本仅识别完整正文 `ok`，不把任意 HTTP 2xx、空正文、HTML、配额或重复错误视为成功；此字面量只在本地合成 fixture 验证，未确认供应商真实成功响应契约，其他响应均保守阻断。
- 核验列表须为有效数组（允许既有包装格式）；空响应、null、无效 IP 或损坏条目均返回错误，不能过滤后当作空列表解除删除屏障。
- 精确 marker 阳性只证明本安装操作归属，不能证明失联的远端处理已退出。即使恢复归属，也不会自动回收该条目或解锁；当前没有自动、定时或强制解除接口。若供应商不能提供可验证完成证据，保守阻塞可能持续存在。
- 未取得发送许可的 prepared pending 可通过状态 CAS 撤销；发送许可和屏障同事务落地后，即使尚未真正发包也不推断为未发送。
- 供应商必须原样返回备注标记才能恢复管理归属；备注被供应商或人工改写时，保守地不认领该条目。这种情况可能保留不可自动回收的记录，但不会据此删除手工条目。
- UID、有效服务地址、UKEY 变化及 A→B→A 通过随机 revision 隔离归属。账号屏障键为 `integration.xiequ.operation.v2:` 加 SHA-256(修剪后的 UID + 换行 + 规范化 BaseURL)，不含 UID/UKEY 明文，也不含 UKEY 或 revision，所以换密钥不能绕过。规范化统一协议/主机大小写、默认端口、空路径和解码后路径的转义拼写；同主机端口的 `/api`、`/%61pi`、`/a%70i` 使用同一账号，不换 revision。可能对服务器区分的转义保守合并，但不会凭编码换屏障。
- 升级不删除或覆盖旧 `operation.v1` journal。旧摘要仅在与当前配置的旧摘要或新规范摘要相等时证明归属，在持配置锁的事务中仅补充 `account` 摘要，原 token、scope、操作内容和未知状态保留。只读时可将已证明的 scope 映射到有效账号以恢复归属，不写完成证明。旧状态的 scope/受管记录只在当前配置可证明匹配时转换；不同 revision 不继承。
- journal 的 `account` 一旦存在，须为规范小写、64 位十六进制 SHA-256 字符串；空串、null、其他 JSON 类型、非法字符、错误长度及大小写均保守报错。该检查先于 completed 判断，损坏完成态也不会被忽略。v2 还必须有与当前账号键相符的 account；读取、发送许可、完成转换和 pending 恢复共用校验，错误时不改原 journal 字节、token、scope 或 marker。
- 规范摘要只证明格式，不提供供应商账号认证或域名别名证明。旧 v1 的 `account` 是本地数据库中由持配置锁的迁移写入的绑定材料：未完成且未绑定的记录仍须与当前可重算的旧/规范摘要相等；已绑定异账号记录不阻塞当前账号，但未完成绑定若与当前可重算的旧键证明矛盾则报错。有效完成的旧 v1 不再占用屏障。数据库写入完整性是此契约的信任边界，无法检测攻击者将全部字段改成另一份语法合法记录；不会用无凭据摘要宣称未知地址属于同一真实账号。
- 无法归属的旧未知摘要不能反推 UID/URL，也不能枚举全部编码别名；它会使该数据库内所有后续谐趣变更保守失败，保留原 journal，不因改配置、读状态、重启或已禁删而解除。已完成的有效旧记录不新增屏障；损坏 journal 返回真实错误。此升级策略不支持依靠旧进程继续写 v1 的滚动混用来获得保证，升级前须等待旧执行真实退出。
- 不同有效 BaseURL/UID 被视为不同账号；域名别名、点路径、网关重写或多个地址实际指向同一真实账号未有供应商证据，不能声称已解决这些服务端等价关系。已证明属于其他账号的屏障不污染当前账号；未证明的旧摘要按上述全局保守策略处理。
- advisory 会话锁只优化普通刷新互斥，不能证明旧 HTTP 服务端退出；持久账号屏障才是变更准入依据。独立数据库安装和外部人工操作不受本安装屏障约束。
- 本工具停止自动远端删除和回收，包括曾由本安装添加并持有完整 marker 的条目。供应商仅按 IP 删除，无原子身份条件；重复读取列表仍无法排除读后手工重建。满额且当前出口缺失时，保留远端条目，返回 `quota_full`、`ok=false`、`added=false`、`removed=[]`，提示用户到供应商后台人工处理；不会先 Add 或 Delete，也没有强删按钮或接口。归属跟踪继续保留用于诊断，旧 IP-only 不补标接管；历史未知 Delete 不因停止新 Delete 而解除。

前端须保留严格数组校验，并将默认地址及说明改为 HTTPS；后端不接受通过放宽类型或关闭证书校验解决配置问题。
