# Xiequ 白名单安全与恢复约定

- 管理接口只允许 HTTPS，必须验证证书；不会跟随重定向或降级到 HTTP。
- 默认地址为 `https://op.xiequ.cn/IpWhiteList.aspx`。历史 HTTP 配置不会被自动改写，刷新将在发送请求前失败；请显式核对并保存 HTTPS 地址。
- 本次仅以不带 UID/UKEY 的请求确认 HTTPS 端点可达，未验证真实账号或白名单修改能力。
- 设置接口的 `state.managed_ips` 始终返回数组，包括全新配置和空状态；其他字段继续按原契约校验。存储状态损坏仍返回错误。
- 网络请求前保存本次尝试时间；请求取消后使用独立的 3 秒有界上下文保存结果。自动刷新继续遵守原有冷却间隔，手动刷新仍可显式跳过冷却。
- Add 之前持久化当前身份及配置代次的 pending-add，并在备注尾部附加随机操作标记。备注总长保持在 80 字节内，必要时按完整字符截短用户备注。
- 远端提交后响应或验证丢失时，不立即继续删除或重试；下一次刷新从持久化 pending-add 核验 IP 与原操作标记。新建 Manager 可恢复该记录，未经核验不计为成功。
- 供应商必须原样返回备注标记才能恢复管理归属；备注被供应商或人工改写时，保守地不认领该条目。这种情况可能保留不可自动回收的记录，但不会据此删除手工条目。
- UID、服务地址、UKEY 变化及 A→B→A 通过随机 revision 隔离归属。状态写回另有版本 CAS；跨 Manager 刷新在同一 PostgreSQL 身份代次持独占会话锁，避免并发远端变更。
- 满配额时仅回收已核验的托管旧 IP；手工条目和当前出口不删除。

前端须保留严格数组校验，并将默认地址及说明改为 HTTPS；后端不接受通过放宽类型或关闭证书校验解决配置问题。
